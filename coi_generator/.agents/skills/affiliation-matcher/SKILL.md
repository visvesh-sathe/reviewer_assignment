# Affiliation Matcher (Conflict of Interest Matrix Generator)

This skill evaluates institutional Conflicts of Interest (COI) between conference reviewers and submitted papers. It consumes the **pre-processed affiliations file** generated by the Python scrubber (`intermediate_files/paper_id_and_affiliations.csv`) and queries a **local Ollama instance** running `qwen2.5:7b` with zero external API keys or logins.

---

## Workflow Overview

```
input_files/cfg_reviewer_expertise.csv (Reviewers & Institutional Affiliations)
intermediate_files/paper_id_and_affiliations.csv (Pre-processed by Python Scrubber)
              │
              ▼
   Local Ollama (qwen2.5:7b) at http://localhost:11434/v1
   (OpenAI-Compatible endpoint: OPENAI_BASE_URL="http://localhost:11434/v1", OPENAI_API_KEY="ollama")
              │
              ├──► output_files/cfg_coi.csv (Binary COI Matrix)
              ├──► input_files/cfg_coi.csv (Editable Staged Matrix)
              └──► output_files/coi_report.txt (Itemized Audit Log with Reasoning)
```

---

## Expected Input Files

1. **Pre-Processed Paper Affiliations (`intermediate_files/paper_id_and_affiliations.csv`)**:
   - Generated by the Python scrubber from `cfg_paper_info.csv`.
   - Contains two columns: `paper_id` and `affiliations` (semicolon-separated institutions). Author names and paper titles are scrubbed to preserve double-blind integrity.
2. **Reviewer Expertise (`input_files/cfg_reviewer_expertise.csv`)**:
   - Contains reviewer names (`Firstname`, `Lastname`) and their primary institution in the `Affiliation` column.

---

## Local LLM Configuration (Zero API Keys)

- **Server Endpoint**: `http://localhost:11434/v1` (OpenAI-compatible)
- **Model**: `qwen2.5:7b`
- **Environment Variables**:
  ```bash
  export OPENAI_BASE_URL="http://localhost:11434/v1"
  export OPENAI_API_KEY="ollama"
  ```

## Institutional Matching Rules & Reasoning Guidelines

The model must identify every case where a reviewer's affiliation conflicts with any author affiliation of a paper:
1. **Acronyms & Abbreviations:** Intelligently match standard institutional acronyms and aliases:
   - `MIT` = Massachusetts Institute of Technology
   - `GT` / `Georgia Tech` = Georgia Institute of Technology
   - `UIUC` = University of Illinois Urbana-Champaign
   - `PKU` = Peking University
   - `THU` = Tsinghua University
   - `SNU` = Seoul National University
   - `KAIST` = Korea Advanced Institute of Science and Technology
   - `UCB` / `UC Berkeley` = University of California, Berkeley
   - `UCSD` = University of California, San Diego
   - `UCLA` = University of California, Los Angeles
   - `SJTU` = Shanghai Jiao Tong University
   - `SKKU` = Sungkyunkwan University
   - `Notre Dame` = University of Notre Dame
2. **Industry Labs & Subsidiaries:**
   - `Intel` = Intel Corporation = Intel Labs
   - `NVIDIA` = Nvidia Corporation
   - `Samsung` = Samsung Electronics = Samsung Advanced Institute of Technology (SAIT)
   - `Qualcomm` = Qualcomm Incorporated = Qualcomm AI Research
   - `IMEC` = Interuniversity Microelectronics Centre
   - `Broadcom` = Broadcom Inc. = Avago
   - `IBM` = IBM Research
3. **Ignore Role Noise:** Disregard generic non-institutional strings such as `Student`, `Professor`, `Engineer`, `Postdoc`, `Unknown`, `N/A`.

## Execution Instructions

Run the affiliation matching helper script against the local Ollama server:

```bash
python3 coi_generation.py \
  --base-url "http://localhost:11434/v1" \
  --model "qwen2.5:7b" \
  --scrub-output "intermediate_files/paper_id_and_affiliations.csv" \
  --reviewer-exp "input_files/cfg_reviewer_expertise.csv" \
  --output-coi "output_files/cfg_coi.csv" \
  --editable-coi "input_files/cfg_coi.csv" \
  --report-output "output_files/coi_report.txt"
```

Or run headlessly using `agy`:
```bash
OPENAI_BASE_URL="http://localhost:11434/v1" OPENAI_API_KEY="ollama" agy -p "/affiliation-matcher" --model qwen2.5:7b --dangerously-skip-permissions
```

---

## Outputs Generated

- **`output_files/cfg_coi.csv`**: A binary matrix ($N_{\text{papers}} \times N_{\text{reviewers}}$) where `1` indicates an institutional conflict and `0` indicates no conflict.
- **`input_files/cfg_coi.csv`**: Staged copy for downstream reviewer allocation solvers.
- **`output_files/coi_report.txt`**: Detailed audit report listing every detected conflict, matching institutional names, and reasoning.
